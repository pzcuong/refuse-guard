\begin{abstract}
Large-language-model code analyzers read prose the defender does not
control: a planted advisory comment moves the false-positive rate on
benign code from $.0625$ to $.70$ for granite-3.3-2b (51
benign$\to$vulnerable flips, 0 reversals, exact McNemar $p{=}8.9{\times}10^{-16}$,
$n{=}80$) and from $.7125$ to $.9875$ for Llama-3.2-3B, while the standard
countermeasure---an AST-gated comment/docstring strip---costs cue-based
detectors (recall $.167\to.042$ for Llama-3.2-3B). We present
\textbf{EVIDA}, a pre-registered pipeline that treats the verdict on an
attacked file and on its stripped counterfactual as two views: disagreement
raises an alarm, a four-checker code-evidence bank adjudicates with a
frozen fallback, and the policy verifies or abstains---never silently
choosing a view. The pilot (764 paired units,
two 2--3B models, gates frozen before any generation) answers the
registered recovery question \emph{negatively}: corruption recovery
$.2182$ ($12/55$) versus $.3273$ ($18/55$) for strip-only---below the
$.40$ gate and below strip-only itself---and the disagreement alarm is
noise on uncorrupted units (precision $.2111$; falsifier F3 fires).
End-to-end over the 55 events $\cup$ 146 clean units, every defense
variant is net-harmful against doing nothing (errors 68 EVIDA / 115
strip-only / 55 no-defense), and pipeline recall on vulnerable units
(.527) trails the raw analyzer (.571). What
survives is directional only: defense-induced errors on clean units fall
$.5342\to.1712$ ($p{=}2.2{\times}10^{-16}$). The registered verdict is
FAIL (mechanism-invalid); we decompose the failure and delimit where
counterfactual disagreement can carry a defense. Safety claims are
scoped to a cache-only base-model contrast---no safety prompt
reached the pipeline.
\end{abstract}

\section{Introduction}\label{sec:intro}
Open-source package and code analyzers built on local large language models
read exactly the artifact an attacker can author: supply-chain attacks
deliver malicious packages~\cite{ladisa2023sok,ohm2020backstabbers,
duan2021maloss}, deployed detectors learn from metadata and installation
behavior~\cite{huang2024donapi,zhang2025cerebro,gao2025malguard,
halder2024memptec}, and LLM-based triage is entering
practice~\cite{zahan2025npm,han2023howfar,sun2024llm4vuln}. When the
analyzed content contains prose---comments, docstrings, advisory-style
notes---the prose is untrusted context in the sense of indirect prompt
injection~\cite{yi2023bipia,liu2024autopi}, and it is semantically inert:
nothing it says executes, yet it can steer the verdict.

Prior work in this program measured the channel. In the vulnerability
domain, untrusted context corrupts verdicts toward flagging (a
false-positive channel) and open 2--7B models essentially never
refuse~\cite{refuseguard2026,campbell2026drb,li2026beyondrefusal}. In the
package domain the same program measured an in-package advisory that moves
verdicts family-dependently, and an AST-gated comment/docstring strip
(D1) that removes the channel where it inflates detection but deletes the
detection cues of a second model family. Three measured facts anchor this
paper. \textbf{(M1)} On function-level snippets from four CWE families, a
near-injection advisory raises granite-3.3-2b's false-positive rate on
benign code from $.0625$ to $.70$ ($\Delta$.6375; 51 benign$\to$vulnerable
flips, 0 reversals, exact McNemar $p{=}8.9{\times}10^{-16}$, $n{=}80$) and
Llama-3.2-3B's from $.7125$ to $.9875$ ($\Delta$.275; 22 flips, 0
reversals). \textbf{(M2)} D1, gated by AST equivalence, reverts all four
advisory-induced verdict changes on granite (exact $p{=}.125$) but
suppresses llama's malicious recall $.167\to.042$: the four lost
detections are byte-identical comment-cued snippets, so the defense removes
the model's cues along with the attack. \textbf{(M3)} Stripping is
provably attack removal: on all 38 gated package samples the stripped
attack file equals the stripped original byte-for-byte.

These facts pose a question that strip-only defense cannot answer: can the
analyzer \emph{itself} notice that a verdict was corrupted, decide which
view is right from code evidence alone, and abstain when neither is
supported---all without ever seeing ground truth at runtime? EVIDA
(Evidence-grounded Invariant Verdict Analysis) is our pre-registered
answer: run the analyzer on the attacked file and on its stripped
counterfactual (a view pair whose equality properties M3 establishes);
treat view disagreement as an alarm, never as a verdict rewrite; adjudicate
alarms with a bank of four static checkers (CWE-190, CWE-200, CWE-416,
CWE-476) that validate claim locations in the AST and data-flow slices;
route undecidable cases to a frozen CodeBERT fallback threshold; and
guarantee the invariant that every no-evidence path is a counted fallback
or abstention, never a silent view choice.

The pilot was executed exactly as registered, and its registered verdict is
\textbf{FAIL}---a mechanism-invalid result that we report as the primary
finding. On the registered granite corruption population (55 events), EVIDA
recovers $.2182$ ($12/55$) of corrupted verdicts against a frozen $.40$
gate, and \emph{loses} to the strip-only comparator ($.3273$, $18/55$; all
6 discordant pairs against EVIDA). The disagreement alarm---the
mechanism's foundation---has precision $.2111$: most alarms fire on clean
units where stripping the file's \emph{own} comments changes the verdict,
not on corrupted files. The registered falsifier F3 fires
(Holm-adjusted $p{\approx}0$). What survives is directional and
reproducible --- but net-harmful end-to-end: the adjudicate-then-abstain
layer cuts the rate of silent defense-induced errors from $.5342$ to
$.1712$ pooled (exact McNemar $p{=}2.2{\times}10^{-16}$, 53 discordant
pairs, all one-directional) and from $.1951$ to $.0976$ on the cue-loss
model, yet over the union of events and clean units every defense variant
commits more errors than running the raw analyzer (55), EVIDA included
(68), and its recall on vulnerable units (.527) trails the raw analyzer
(.571). Safety-preservation was measured only as a cache-only base-model
contrast; no safety prompt reached the pipeline.

Our contributions:
\begin{enumerate}
  \item \textbf{A registered mechanism test, executed as registered.} Gates
  G1--G5, falsifiers F1--F4, and tripwires T1/T2 were frozen before any
  generation; the pilot ran pass-to-pass (a first pass with a disclosed
  cache-key defect is archived and also fails the gates), and a later
  cache-only re-execution reproduced every endpoint bit-identically
  (\S\ref{sec:design}).
  \item \textbf{The first paired measurement of strip-only recovery on the
  false-positive channel.} CRR(D1-only) $=.3273$ ($18/55$) on the granite
  FP population had never been measured before (only the 4-event
  recall-inflation channel had, in M2); it is the correct baseline any
  future adjudication defense must beat.
  \item \textbf{A negative verdict with a mechanism decomposition.} The
  recovery failure decomposes into three measured components: (i) in
  $37/55$ corruption events the two views \emph{agree} on the corrupted
  verdict, so the alarm never fires; (ii) the checker bank's SUPPORT
  decisions false-endorse verdicts on benign code that structurally
  resembles vulnerable code; (iii) the frozen fallback contributed
  incorrect finals on the clean population. Each component is measured,
  not conjectured (\S\ref{sec:ablations}).
  \item \textbf{An end-to-end accounting that the defense loses.} Over the
  union of the 55 corruption events and the 146 registered clean units,
  every defense variant is net-harmful against running the raw analyzer
  (errors $68$ EVIDA, $115$ strip-only, $55$ no-defense), and EVIDA's
  recall on vulnerable units (.527) is below both the raw analyzer (.571)
  and its own stripped view (.628). The DIER reduction is real
  ($.1712$ vs.\ $.5342$ pooled, $p{=}2.2{\times}10^{-16}$) but compares
  two net-harmful variants on the clean side only; the guard objective
  failed its absolute $.05$ gate and the end-to-end frontier is shown,
  not hidden (\S\ref{sec:results}, Table~\ref{tab:netutil}).
\end{enumerate}

\section{Related Work}\label{sec:related}
\textbf{Malicious-code detection and LLM triage.} Behavior-sequence
detectors map installation-time traces (DONAPI~\cite{huang2024donapi},
Cerebro~\cite{zhang2025cerebro}), MalGuard targets real-time PyPI
detection~\cite{gao2025malguard}, MeMPtec uses
metadata~\cite{halder2024memptec}, and LLM triage of npm packages is
measured in~\cite{zahan2025npm}. None of these study interference from
prose inside the analyzed file, which is the channel EVIDA defends.
\textbf{LLM vulnerability analysis.} Function-level LLM vulnerability
detection and its evaluation pitfalls are documented
in~\cite{ding2025primevul,han2023howfar,sun2024llm4vuln}; the paired
(no ground truth at inference) discipline here follows the no-oracle rule
of that line.
\textbf{Untrusted context and injection.} BIPIA benchmarks indirect prompt
injection and defenses~\cite{yi2023bipia}; automatic injection attacks are
systematized in~\cite{liu2024autopi}. Modern injection defenses include
query structuring (StruQ~\cite{chen2024struq}), design-time information
control (CaMeL~\cite{debenedetti2025camel}), and layered code-context
sanitization (CodeSentinel~\cite{cheng2026codesentinel}); none is
reproduced or run in this pilot --- EVIDA's trusted view is the same
tree-sitter sanitization family as CodeSentinel's first layer, which is
precisely why the strip-only comparator below also represents that
defense class. EVIDA differs from pre-model sanitization in guarantee
shape: sanitization transforms the input before the model and offers no
signal when corruption survives it, whereas EVIDA post-hoc compares the
two views, adjudicates with code evidence, and counts every unevidenced
path (verify-or-abstain).
\textbf{Positioning: consistency-based reliability checking.} The
counterfactual alarm is an instance of the consistency/redundancy
tradition: perturbation-consistency hallucination detection
(SelfCheckGPT~\cite{manakul2023selfcheckgpt}), sample-and-aggregate
decoding (self-consistency~\cite{wang2023selfconsistency}), and the
classical multi-version and recovery-block schemes for software fault
tolerance~\cite{avizienis1985nversion,randell1975recovery}. EVIDA
instantiates two-view consistency with one difference that matters here:
its second view is \emph{executable-content-equivalent by construction}
(AST-gated strip; byte-equality M3), so a disagreement is attributable to
the removed prose rather than to sampling noise. The pilot's negative
result is therefore evidence about this design point --- consistency
between a file and its de-prosed twin --- and not about consistency
checking in general.
\textbf{Safety-layer line of this program.} A companion measurement
study~\cite{refuseguard2026} established refusal absence and
verdict-corruption under untrusted context in the vulnerability domain;
concurrent work documents defensive-refusal
bias~\cite{campbell2026drb} and aligned-vs-abliterated
behavior~\cite{li2026beyondrefusal}. This paper is the first
\emph{defense} pilot of the program: it inherits the measured corruption
populations (M1) and the audited strip machinery (M2--M3) and registers a
frozen go/no-go test of the adjudication mechanism.
\textbf{Selective prediction.} The verify-or-abstain policy instantiates
selective prediction for verdict pipelines: abstention is budgeted and
reported (UAC, abstain share) rather than implicit; the pilot's zero-abstain
outcome (\S\ref{sec:results}) means the abstention arm remains untested
under pressure---a stated limitation, not a claimed property.

\section{Threat Model}\label{sec:threatmodel}
\textbf{Attacker.} The attacker controls prose inside the file the
defender's LLM will read: comments, docstrings, or an advisory-style note.
The prose is non-executable and semantically inert by construction
(comment-only injections gated by a tree-sitter equivalence check), so any
verdict change is caused by the model reading untrusted text. Two measured
attack arms instantiate the threat: \textbf{C5\_near}, a feature-based
near-injection advisory on function-level snippets from four CWE families
(anti-leakage: no label, CWE, or CVE token in the advisory; benchmark
\texttt{bench\_attack\_v2}, sha256\_16 \texttt{7e8ed42421a7c2d0}); and
\textbf{P2}, an advisory prepended to real package files
(AST-gated). The attacker's goal is bidirectional: suppress detections of
genuinely malicious code, or inflate detections---including false
positives on benign code.
% SRC: prereg §1.2 (bench_attack_v2 sha 7e8ed42421a7c2d0, anti-leakage
% clause) and §1.1 S1/S2 arm definitions; C5_near/P2 corruption effects M1
% and §6 below.

\textbf{Defender.} The defender runs a local 2--3B analyzer (granite-3.3-2b,
Llama-3.2-3B) and may post-process its output. The defender does not know
which files are attacked. The EVIDA pipeline never sees ground truth at
runtime: the alarm reads only the two verdicts; the adjudicator reads only
static code evidence; refusals are never converted into verdicts. Labels
enter only at scoring time.
% SRC: prereg §1.3 (label access / anti-oracle clause, no-oracle charter
% §11); §1.1 model roster.

\textbf{Out of scope (declared pre-run).} Executable payload semantics; the
string-literal channel (the strip keeps strings, so a corrupted-string
attacker is unmitigated); an attacker who corrupts \emph{both} views
(comment-free attack files defeat the counterfactual pair by
construction); and adaptive attacks, which are anticipated but not run
(\S\ref{sec:adaptive}). The measured realization-internal boundary of the
counterfactual is view agreement: in $37/55$ corruption events the two
views already agree on the corrupted verdict, which caps any
two-view-adjudicating defense's recovery at $18/55{=}.3273$
(\S\ref{sec:ablations}).

% integrity defense) and known_limitations in evida_analysis.json.

\section{Method: EVIDA}\label{sec:method}
EVIDA is a five-stage pipeline over one analyzed file. No training occurs;
all model calls are greedy (temperature $0$, seed $1234$) and served
through a prompt-hash cache whose key includes the model revision.
% SRC: prereg §1.8 (gen_cfg frozen: temp 0.0, do_sample false, seed 1234;
% cache key includes revision per src/models/llm_harness.py:8; "drift =
% cache miss = FAIL LOUDLY").

\textbf{(1) Raw view.} $V_{\mathrm{raw}}$: the verdict of the analyzer on
the file as given (cached from the upstream measurement arms: C0/C5\_near
for snippets, P0/P2 for packages).
% SRC: prereg §2 step 1.

\textbf{(2) Trusted view.} $V_{\mathrm{trusted}}$: a newly generated
verdict on the \emph{stripped} file, produced by the audited D1 machinery
(tree-sitter comment and Python-docstring removal; string literals kept;
AST re-parse equivalence gate). The pair (attacked file, stripped file) is
the counterfactual: M3 establishes that \emph{on the 38 gate-passing
package samples} the stripped attack file is byte-identical to the
stripped original, so the trusted view is ``the same executable content,
minus prose.'' Gate-failure handling is registered before conditioning: a
gate FAIL excludes the unit and is disclosed, never silently conditioned
(realized here: 0 S2 exclusions; the S1 C/C++ fragments ran under the
registered lenient-canonical gate mode, $160/160$, since strict
clean-parse is unattainable on C fragments).
% SRC: prereg §2 step 2 (machinery packguard/defense_strip.strip_comments;
% strings kept); M3: reports/round12/V1_report.md:48,116,194 (38/38
% byte-equality, 45/45 re-strip).

\textbf{(3) Counterfactual disagreement alarm.} alarm $=$ ($V_{\mathrm{raw}}
\ne V_{\mathrm{trusted}}$), both views parsed. The alarm is \emph{not} a
rewrite: it only triggers adjudication. This is the registered mitigation
for the known failure mode of view-based defenses (picking the wrong view).
% SRC: prereg §2 step 3 ("alarm ≠ rewrite").

\textbf{(4) Code-evidence adjudicator.} A bank of four registered checkers
--- CWE-190 (arithmetic on unvalidated size), CWE-200 (information flow to
a sink), CWE-416 (free-then-use ordering in the CFG), CWE-476
(null-dereference path in the CFG) --- validates the flagged verdict
against tree-sitter AST locations and CFG/data-flow slices of the
function-level code. Claim-level outcomes as \emph{registered}:
\textbf{SUPPORT} $\to$ final $= V_{\mathrm{raw}}$ (the claim is backed by
code); \textbf{REFUTE} $\to$ final $= V_{\mathrm{trusted}}$ (the claim
location/pattern is absent from the slice); \textbf{UNDECIDABLE} $\to$ a
frozen fallback: CodeBERT (125M) \cite{feng2020codebert} at a
pre-registered argmax-MCC threshold $\tau{=}.5481$, with an ABSTAIN flag
if the fallback yields no usable verdict. The checkers never see labels.
\emph{As implemented}, the outcome rule is direction-symmetric rather than
claim-relative, and the manuscript's frozen description above is
therefore incomplete (disclosed implementation finding): SUPPORT and
REFUTE are view-relative labels, and pattern absence endorses the benign
verdict through whichever view cast it --- all $122$ SUPPORT paths that
record a pattern state carry
\texttt{pattern\_state=pattern\_absent} with $V_{\mathrm{raw}}$ benign,
and all $51$ REFUTE paths with
\texttt{pattern\_state=pattern\_absent} have $V_{\mathrm{raw}}$
flagging-vulnerable, i.e.\ REFUTE switches to the (benign) trusted view.
A second scope fact: the checker bank is registered on the four RQ8
snippet families, so on real package files (S2) the checkers are
structurally unreachable and the fallback is the de facto decider ---
all $41$ fallback calls are S2 units (\S\ref{sec:results}).

\textbf{(5) Verify-or-abstain policy.} No branch of the pipeline silently
selects a view; every no-evidence path is a counted fallback or a counted
abstention (abstain budget). A refusal is never mapped to a verdict.
% SRC: prereg §2 step 5 + §1.6 secondary 4 (refusal never mapped to
% verdict).

\textbf{Checker validation protocol (before any real adjudication was
read).} Inject-and-perturb synthetic cases with labels by construction
(pattern inserted into clean code $=$ SUPPORT-known; pattern deleted from
vulnerable code $=$ REFUTE-known), four per family: $16/16$ correct
(synthetic precision $1.0$, synthetic recall $1.0$). This is a mandatory
disclosure, not a gate: the synthetic labels bound what the checker bank
can certify, and \S\ref{sec:ablations} shows the gap between synthetic and
real distributions.

\section{Experimental Design}\label{sec:design}
\textbf{Registration.} The pilot was pre-registered and frozen
(2026-09-30) \emph{before} any round-17 generation, with a filesystem
check at freeze showing no round-17 artifacts, at git commit
\texttt{fb8988ad1ae9ef486856636c6c71129c54672e00}; the frozen config is
\texttt{configs/evida.yaml} (sha256\_16 \texttt{88971fa41e22ff59},
created at freeze time). Hypotheses H-E1--E4, endpoints, gates, and
falsifiers were locked in the registration. \emph{Registration status
disclosure:} this registration is repository-internal --- the freeze is
attested by the recorded commit and file timestamps, with no external
timestamping (OSF registration is queued, not done, at submission time);
the corruption populations, strip equivalence, and endpoint code ship in
the anonymized artifact supplement so reviewers can re-derive the
endpoints rather than trust the freeze.

\textbf{Populations (frozen manifests, evaluation-only; no new splits).}

\textbf{Endpoints.} \textbf{Primary: CRR} (Corruption Recovery Rate) on
the registered granite pooled corruption population (S1-benign FP events
$\cup$ S2-malicious recall-inflation events): an event is a sample whose
attack-arm verdict differs from its clean-baseline verdict; the event is
recovered iff the pipeline's final verdict equals the clean baseline.
CRR(EVIDA) counts the pipeline final; \textbf{CRR(D1-only)} counts the
trusted-view verdict alone---measured on the FP channel here for the first
time. CRR is \emph{verdict restoration} (fidelity to the clean baseline's
behavior), \emph{not} correctness restoration: on the recall-inflation
stratum the clean baseline is benign against
$y_{\mathrm{true}}{=}$vulnerable, so a ``recovered'' event re-breaks a
correct detection of malicious code; truth-conditioned recovery is
reported separately in \S\ref{sec:generalization}. \textbf{Secondary: DIER} (Defense-Induced Error Rate) on clean
samples with a correct baseline verdict (registered denominators:
granite 105, llama 41, pooled 146), three states \{correct, incorrect,
abstain\}, DIER $=$ incorrect/denominator (abstain is not incorrect);
strict-DIER $=$ (incorrect$+$abstain)/denominator reported alongside,
never gated; \textbf{alarm precision/recall}; \textbf{UAC} (usable-answer
coverage, floor $.95$); per-family/per-channel strata; safety
preservation. The MPIE (minimum practically important effect) was
registered as $\Delta$CRR $\ge .15$ absolute.

\section{Ablations and Mechanism}\label{sec:ablations}
\textbf{Where the mechanism breaks: three measured components, with the
dominant failure direction named.}
\emph{(i) The counterfactual is inert on most events --- and this caps
every gate.} In $37/55$ corruption events the raw and trusted views
\emph{agree} on the corrupted verdict ($67\%$): stripping the advisory
out of the attacked file does not change the verdict, no alarm fires, and
adjudication is unreachable. Recovery is possible only on the $18/55$
events where views differ --- and on \emph{all 18} of those the stripped
view is already correct --- so the CRR ceiling for \emph{any} adjudicator
over these two views is $18/55{=}.3273$, below the registered G1 gate of
$.40$: G1 was unsatisfiable in realization, before any checker ran.
\emph{(ii) The dominant measured cost is false-negative creation, not
benign false positives.} On the vulnerable side, 64 units have a correct
trusted detection \emph{destroyed} by the pipeline (trusted
$=$ vulnerable, final $\ne$ vulnerable): 62 via checker-SUPPORT on
\texttt{pattern\_absent} and 2 via the fallback. Per checker: CWE-200 24,
CWE-190 21, CWE-416 16, CWE-476 1; per model: granite 59, llama 5; per
source: S1 62, S2 2. Overall, SUPPORT kept a wrong final verdict in
$69/135$ paths (62 vulnerable-side, 7 benign-side). \S\ref{sec:method}'s
implemented-rule disclosure explains the sign: pattern absence endorses
the benign verdict, so benign-looking vulnerable code gets its correct
detection overwritten. The benign-lookalike framing (SUPPORT false-
endorsement on clean units) is real but secondary --- the unreported cost
ran the other way. Both directions are invisible to the synthetic
validation ($16/16$ on labels-by-construction). \emph{(iii) The frozen
fallback hurts on clean units.} Of the 41 fallback calls, 19 fall inside
the registered clean population and 13 of those end in an incorrect
final (9/15 on granite-clean; 4/4 on llama-clean --- every llama-clean
fallback call ends incorrect), so the fallback contributes directional
losses to the clean-side error budget.

\section{Anticipated Adaptive Attacks (Not Run)}\label{sec:adaptive}
No adaptive evaluation exists in this pilot. Charter \S14 mandates an
adaptive red-team stage; it was not reached (the state machine stops at
the pilot verdict), and this section is therefore \emph{anticipation
grounded in measured structure}, not an adaptive experiment. Likewise, no
modern injection defense is reproduced: StruQ~\cite{chen2024struq},
CaMeL~\cite{debenedetti2025camel}, and
CodeSentinel~\cite{cheng2026codesentinel} are cited as positioning
(\S\ref{sec:related}), never run; the tables contain the no-defense and
always-abstain operating points (Table~\ref{tab:netutil}) --- the
no-defense row wins. The paper should be read as a registered
negative-result measurement with a scoped mechanism analysis, not as a
validated defense. Each claim below is anchored to a measurement; the
string-literal bypass and the both-views attack remain open by declared
scope (\S\ref{sec:threatmodel}).
% SRC: prereg §4 (pre-declared limitations) + §1.1 S5 read-only.

\textbf{(1) One-directional signatures are learnable.} The corruption
channel is one-directional on both models (granite 51
benign$\to$vulnerable / 0 reverse; llama 22/0): an attacker who knows the
defense class can tune advisories to sit inside the measured acceptance
region rather than at its extreme. The pilot measures the extreme; the
direction asymmetry means threshold-tuned alarms would face a shifting
target.
% SRC: outputs/master/round7_master.json (flip_b2v/flip_v2b rows quoted
% in §1, M1/M2).

\textbf{(2) The defender's own transform is an attack surface.} The
round-12 defense measurement (\S\ref{sec:intro}) is already an adaptive
result without an adaptive attacker: for llama, the comments the strip
removes were the detection cue, so the defense suppresses recall
$.167\to.042$. An attacker needs no injection at all---benign-looking
comments become a liability under the defender's mandatory
preprocessing. EVIDA inherits this surface because its trusted view is
the stripped file.
% SRC: defense_analysis.json (llama P0 .1667 -> P2 .0417 -> P2D1 .0417;
% lost detections comment-cued, byte-identical snippets, family-level
% 1/19) — as carried in prereg §0 M3.

\textbf{(3) Structure mimicry steers the adjudicator.} The checker bank
keys on structural patterns (CWE-190/200/416/476); the measured 213
alarms on non-corrupted units adjudicated without any corruption present
show that benign code already trips view- and evidence-path machinery at
pilot scale. An attacker who shapes benign code toward a pattern (or
strips vulnerable-looking structure) steers SUPPORT/REFUTE decisions; the
synthetic validation cannot see this because its labels are
by-construction.
% SRC: evida_analysis.json endpoints.alarm_quality (FP 213);
% checker_synthetic_validation (labels by construction); mechanism (ii)
% in §8.

\textbf{(4) The abstention arm is the designed adaptive fallback---and is
untested.} Verify-or-abstain guarantees no silent view choice, and the
realized abstain budget is $0/756$ (CI upper $.0049$): the guarantee held
trivially because the path was never exercised. Under an adaptive
attacker, whether the pipeline abstains rather than mis-verdicts is an
open question this pilot cannot answer.

\section{Limitations}\label{sec:limitations}
\textbf{Statistical power.} The primary population realizes 55 events,
below the registered 100--200 band (declared pre-run); the llama-clean
DIER stratum has 41 units with only 4--8 discordant pairs, so its paired
comparison is not statistically resolved ($p{=}.125$; resolution needs
${\ge}6$ one-directional discordants). All inference is
descriptive-at-realized-$n$; the Holm layer covers exactly the four
registered comparisons.
% SRC: prereg §1.4–§1.7; realized counts from evida_analysis.json.

\textbf{Scope.} Prose channel only (comment/docstring/advisory);
string-literal and both-views-corrupted channels out of scope; two models
at 2--3B under MPS bf16 decoding; S3 (E6 IPI pairs) not evaluable at
pilot; no multi-seed sensitivity (the 3-seed policy is registered for
FULL only, which never opened); verifier labels are heuristic with
synthetic-only validation (no human $\kappa$); no adaptive red-team run,
and no reproduced external defense (StruQ/CaMeL/CodeSentinel cited, not
run). On the package channel the checker bank is structurally
unreachable, so the security-critical decisions fell to a frozen 125M
fallback at $.4634$ accuracy (\S\ref{sec:results}).

\textbf{Coverage of the safety channel.} The pilot measures no safety
behavior of the pipeline: the S4 contrast is cache-only and base-model
(per-model keys: qwen, llama --- the primary model granite has no S4
coverage), and no safety record reached adjudication/fallback by
construction. Any claim that verify-or-abstain preserves safety
properties of the \emph{pipeline} is unsupported here and requires a
successor arm.

\textbf{Evidence chain.} The registration is repository-internal with
self-attested freeze (commit + timestamps; no external timestamping at
submission). All endpoints derive from released per-unit artifacts
(\texttt{evida\_decisions.json}, \texttt{evida\_analysis.json}, units
manifest), and every added number in the repair pass is a recompute from

measurement study is cited as an anonymous manuscript without a public
identifier; its load-bearing numbers (M1) are re-established here from
the released \texttt{round7\_master.json} artifact.

\textbf{Status of the method.} The registered verdict is FAIL
(mechanism-invalid) at pilot scale. The clean-side DIER reduction
($.1712$ vs.\ $.5342$) is a directional observation comparing two
net-harmful variants (Table~\ref{tab:netutil}), not a validated defense
property; the guard objective's absolute gate ($.05$) was not met, and
end-to-end the pipeline is harmful against its own raw analyzer. FULL
never opened: no FULL registration exists, and any successor must
re-register and re-pilot under charter \S10 before new generations.

\section{Conclusion}\label{sec:conclusion}
We asked whether an analyzer can recover its own corrupted verdicts by
combining a counterfactual view (stripped file), code-evidence
adjudication (a four-checker static bank with a frozen fallback), and a
verify-or-abstain policy---without ground truth at runtime. The
pre-registered pilot answers no for recovery: CRR $.2182$ vs.\ the $.40$
gate and vs.\ $.3273$ for strip-only --- a gate that realization itself
had capped at $.3273$, since the two views agree on the corrupted verdict
in $37/55$ events; the disagreement alarm that gates everything is noise
(precision $.2111$; F3 fired); and the mechanism decomposes into measured
parts --- inert counterfactuals on $37/55$ events, $64$ correct
vulnerable-side detections destroyed by pattern-absence endorsement and
the fallback, and fallback losses on clean units. End-to-end, over the
union of events and clean units, every defense variant is net-harmful
against the raw analyzer (errors 68/115 vs.\ 55), and the pipeline's
recall on vulnerable units trails the raw analyzer's. The pilot also
fixes values any successor must use: strip-only recovery on the FP
channel is $.3273$ (first measurement), the zero-cost alarm$\to$strip
policy P$^{*}$ matches it and Pareto-dominates the checkered pipeline on
recovery, and the clean-side DIER reduction ($.5342\to.1712$,
$p{=}2.2{\times}10^{-16}$) is directional only --- a comparison of two
net-harmful variants that missed its absolute gate. Per the registered
stopping rule the verdict stands as FAIL (mechanism-invalid), FULL
remains closed behind its preregistration gate, and the negative result
is preserved verbatim: counterfactual disagreement between a file and
its own stripped version is, at 2--3B scale, a measurement of prose
sensitivity --- not, by itself, a corruption detector.
